# Timecode Cue Bridge 0.5.1

LTCを受信し、シーンの指定時刻でOSCとMIDIを送るWindows 11 x64用GUIです。
24 / 25 / 30fpsの非DFに対応します。MTC入力やMTC生成には対応しません。

## 更新・設定の引き継ぎ

アプリを終了してから新しいSetup.exeを実行してください。保存先とアプリ名はv0.2と同じです。
`%APPDATA%\TimecodeCueBridge\cues.json` のv1/v2設定を新しいシーン一覧へ読み込みます。
旧形式の時刻・シーン名・OSCアドレス・整数値を引き継ぎ、`# 時刻 | ...` の行は無効シーンとして取り込みます。
一般のコメントはシーンに変換しません。最初の保存時には元のファイルを同じフォルダーの `cues-before-v0.5*.json` へコピーします。
以前の版へ戻す場合は、そのバックアップをcues.jsonに戻してください。v0.3以降のv3形式はv0.2で読み込めません。
起動時は常にDISARMです。

## シーンを追加・編集する

画面は英語です。操作説明はこのREADMEにまとめています。

1. **Scenes** タブの **+** で追加し、一覧から編集するシーンを選びます。
2. **Scene name** に名前を入力します。**Duplicate** は時刻・OSC・MIDI設定もコピーします。
3. **TRIGGER TIMECODE** のHours / Minutes / Seconds / Framesの数値をクリックし、直接入力します。Enterまたはフォーカスを外すと確定、Escで入力を取り消します。
4. 数値欄を押したまま**上へドラッグすると増加、下へドラッグすると減少**します。通常6pxで1単位、Shiftを押している間は24pxで1単位です。上下矢印キーでも1ずつ変更できます。別のスライダーはありません。
5. 時は0–23、分・秒は0–59、フレームは0–FPS未満に制限します。数値の範囲外は上下限へ補正します。空欄・文字混在・整数として扱えない巨大な数は未確定として赤枠になり、Save & Applyできません。正しい整数に直すかEscで戻してください。シーンを切り替えると不正な未確定入力は取り消します。
6. **Use LTC** は受信中のLTC時刻を設定します。FPS変更後は先にSave & Applyしてください。
7. **Enabled** で有効・無効を切り替えます。**-** で削除、**Restore** で直前の削除を復元。**Sort** で時刻順に並べます。同時刻の複数シーンにも対応します。
8. **Save & Apply** で保存・適用し、**Arm** で自動送信を許可します。起動時と編集中はDISARMです。入力欄を開いた時点でも安全のためDISARMになります。

**I/O Settings** で音声入力とFPSを選びます。入力は1チャンネルです。**Reset All** で全シーンの発火履歴をリセットできます。**Data Folder** は設定・ログのフォルダーを開きます。

時刻はDAWの曲内位置ではなく、受信するLTCの絶対時刻です。
例えばDAWで曲の開始LTCが `01:00:00:00` なら、曲の10秒後のシーンは `01:00:10:00` にします。
LTCはキューより十分前（推奨1秒以上）から流してください。安定した3フレームの受信後にキュー判定を始めます。

## LTCを止めて再開する・Cueの進行状況

LTCの入力取得とCueの発火履歴は別々に管理します。LTCが約250ms届かない場合、デコーダーを自動で初期化して再取得を試みます。停止中の微小ノイズやDC成分で内部の速度追従が崩れても、再生再開後に再取得します。入力が途切れただけならArm状態は維持します。波形が安定してからキュー判定を再開します。入力デバイスそのものの設定変更では引き続きDISARMになります。

| 一覧の表示 | 意味 |
|---|---|
| READY | まだ発火していないシーン |
| FIRED・緑色の背景／左線 | LTCにより発火済みのシーン |
| OFF | 無効なシーン |
| EDITED | 編集後で設定が未適用。Save & Applyが必要 |

一覧上部の `2 / 5 fired` は、有効な5シーンのうち2シーンが発火済みという意味です。FIREDはアプリが発火処理を行った履歴です。送信エラーはステータス／ログで確認してください。相手ソフトの実行完了を確認する表示ではありません。

**重要な変更（v0.5）**：停止・再開、入力喪失、巻き戻しだけでは、発火済みシーンを未発火へ戻しません。意図しない二重送信を避け、選択シーンだけのやり直しを可能にするためです。

- **Reset All**：全シーンをREADYに戻します。LTCは発火時刻より前から再生してください。入力デコーダーはリセットしません。保持中のMIDIノートは停止します。
- **一覧のRearmボタン**：各シーン行の右下にあります。その行のFIREDシーンだけをREADYに戻します。行を選択し直さずに操作できます。READY／OFF／EDITEDの行では無効になります。詳細欄の **Rearm Scene** でも選択シーンを同様にリセットできます。他の発火履歴とArm状態は維持します。LTCを対象時刻より前に戻して再生すると、そのシーンだけ再発火できます。ボタンを押した瞬間には送信しません。
- **Test Scene**：選択シーンを今すぐ手動で送信します。DISARM中でも送信し、自動Cueの発火履歴は変更しません。即座に同じCueを送り直したい場合はこちらを使います。

例：A・B・Cが発火済みでBだけやり直す場合、Bの行にあるRearmをクリック。Bの時刻より前からLTCを再生するとBだけ発火し、A・CはFIREDのまま再送しません。もう一度公演全体を通すときはReset Allを使います。発火履歴は実行中だけの状態で、アプリ再起動やSave & Apply時にはリセットされます。

Windowsの新規インストール・上書き更新時に、現在のユーザーのデスクトップへ **Timecode Cue Bridge** ショートカットを自動で作成します。アプリと同じアイコンを使います。アンインストール時にこのショートカットも削除し、Cue設定・ログは保持します。

画面の右上にアプリのバージョンを表示します。実行ファイル・スタートメニューのショートカット・インストーラーに共通の波形→矢印アイコンを使用します。

## OSC出力

**I/O Settings** のOSC host / UDP portを指定し、各シーンの **OSC** を有効にします。
シーンのOSCアドレスと整数値を指定します。アドレスは受信ソフトで実際に設定したものを使ってください。
整数値は -2147483648〜2147483647。ASCIIのリテラルOSCパスのみで、ワイルドカードは使いません。

## MIDI OUT

1. WindowsでMIDI出力デバイス／仮想MIDIポートを使用できる状態にします。
2. **I/O Settings** → **MIDI OUTPUT** から送信先ポートを選びます。接続後に見つからない場合は**Refresh**。
3. 各シーンの **MIDI** をONにし、種類・チャンネル・番号・値を選びます。
4. **Save & Apply**を押します。ポートがない・開けない場合はARMできません。
5. **Test Scene**で選択した有効シーンを即送信します。これはDISARM中でも送信します。

| 種類 | 番号 | 値 | 動作 |
|---|---|---|---|
| Note ON | ノート番号0–127 | ベロシティ0–127 | 既定100msで自動Note OFF。長さ0なら保持 |
| Note OFF | ノート番号0–127 | リリース値0–127 | 指定ノートをOFF |
| Control Change | CC番号0–127 | コントロール値0–127 | CCメッセージを送信 |

チャンネルは1–16。Note ONの値0はノート停止として扱います。
Note長さはミリ秒で最大60000ms。長さ0で保持したノートは、別シーンのNote OFFやDISARMで止めます。
同じノートを再発火すると、前のNote OFFを送ってからNote ONを送ります。
**MIDI Panic** は自動出力をDISARMし、このアプリが保持するノートを止めます。
DISARM、入力喪失、シーク・巻き戻し、設定変更、全キューリセット、ポート切り替え、終了時にも保持ノートを止めます。
他のアプリのノートを一括停止するCC123は送信しません。OSCとMIDIは同時ONにできます。

送信先ポートはアプリ共通です。シーンごとに別ポートを選ぶ機能、Program Change、SysEx、MTC出力は未対応です。
WindowsのMIDIポートを作成する機能やドライバーのインストールは含みません。

## 同じWindows PC内でDaslight 5へ送る

構成は **本アプリ MIDI OUT → 仮想MIDIポート → Daslight MIDI Input** です。MIDI信号の受け渡しに物理MIDIケーブルや2台目のPCは不要です。照明器具へのDMX出力に必要なDaslight側のインターフェース等は別です。

仮想ポートの一例は [loopMIDI（開発元）](https://www.tobias-erichsen.de/software/loopmidi.html) です。開発元ページの対応表記はWindows 7–10であり、今回Windows 11のご使用環境での動作は検証していません。既に使える仮想MIDIポートがあれば、それを選択することもできます。本Setupには仮想MIDIドライバーを同梱しません。

1. loopMIDIを別途導入・起動し、`TCB to Daslight` などの名前でポートを追加します。使用中はloopMIDIを起動したままにします。同じWindowsユーザーのセッションで各アプリを起動してください。
2. 本アプリの **I/O Settings → Refresh** を押し、そのポートをMIDI OUTPUTに選びます。
3. シーンの **MIDI** をON。例：Message = Note On、Channel = 1、Note / CC = 60、Velocity / value = 127、Note length = 100ms。OSCが不要ならOSCをOFF。**Save & Apply**。
4. Daslight 5の **Settings → MIDI / Audio / BPM → MIDI Devices** で同じポートの **MIDI Input** を有効にします。TCBからDaslightへの片方向入力では、そのポートへのDaslight MIDI Outputは不要です。
5. Daslightの **MIDI Mapping** を開き、割り当てるシーンボタンを選択し、本アプリの **Test Scene** を押して学習させます。手動設定の場合はCreate Note ShortcutからInput・Channel・Noteを一致させます。
6. MIDI Mappingを終了してTest Sceneで動作確認し、Daslightプロジェクトを保存します。Note OFFで停止する割り当ての場合、100ms後に停止するため、Daslight側のOn/Off・トグル／フラッシュ設定を用途に合わせてください。必要なら保持（Note length = 0）と別のNote Offシーンを使います。
7. LTCを発火時刻より前から流し、**Arm** して自動発火を確認します。まずDaslightのMIDI/OSC Watcherで入力メッセージを確認すると、ルーティングとシーン割り当てのどちらの問題か切り分けられます。

ポートが出ない場合はloopMIDIの起動・ユーザー・ポート名を確認し、RefreshやDaslight再起動を試してください。loopMIDI終了時は仮想ポートが消えます。実際のWindows 11 + loopMIDI + Daslightの接続・シーン起動は未検証です。

参考： [Daslight公式ダウンロード／マニュアル](https://www.daslight.com/en/download.htm)、[Daslight 5公式マニュアル（1.4）](https://eu-litterature.n-g.co/Release/daslight_5_manual_en.pdf) のMIDI章・MIDI/OSC Watcher章。公式資料をもとにした接続手順です。

## 保存・削除

インストール先は `%LOCALAPPDATA%\Programs\TimecodeCueBridge`。
Windowsの「設定 → アプリ → インストールされているアプリ」からアンインストールできます。
Cue設定とログは `%APPDATA%\TimecodeCueBridge` に保存し、アンインストール時も保持します。
アプリを起動したままの更新・削除は拒否します。署名なしのビルドです。

## 検証状況・制限

今回実施したテストと未検証項目はBUILD_REPORT_JA.mdを参照してください。
